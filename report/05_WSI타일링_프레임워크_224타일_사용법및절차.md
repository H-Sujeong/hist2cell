# WSI 타일링 — `WSI_tile_sampling_framework` 로 224×224 타일 좌표 추출하기

이 문서는 **whole-slide image(WSI, `.svs` 등)를 224×224 타일로 자르는** 방법을,
이 repo 와 도구를 처음 보는 사람도 그대로 따라 할 수 있게 정리한 것이다.
실제 적용 예시로 TCGA-LUAD 슬라이드 3장을 타일링한 결과를 함께 싣는다.

---

## 0. 먼저 — "타일링" 이 무엇이고 어떤 도구를 쓸지

WSI 한 장은 보통 수억 픽셀(예: 36000×21000)이라 통째로 모델에 못 넣는다.
그래서 **조직이 있는 영역만 골라 작은 정사각형(여기선 224×224 px)으로 쪼개는** 작업을
타일링(tiling) 또는 패칭(patching)이라고 한다.

이 repo 에는 WSI 를 다루는 경로가 **두 가지** 있다. 목적이 다르므로 헷갈리지 말 것:

| 경로 | 코드 | 산출물 | 언제 쓰나 |
|---|---|---|---|
| **타일링 프레임워크** | `WSI_tile_sampling_framework/` | 타일 **좌표** HDF5 + 썸네일 + 조직 mask | 조직 영역의 타일 좌표만 필요할 때. 본 문서 주제 |
| 추론용 prep | `prep/prepare_wsi_for_inference*.py` | PyG `.pt` (모델 입력 그래프) | Hist2Cell 추론까지 바로 갈 때 → `report/02`, `03` 참고 |

**본 문서는 첫 번째(타일링 프레임워크)** 를 다룬다.
프레임워크는 패치 이미지 파일을 직접 저장하지 않고 **좌표(HDF5)** 만 남긴다.
실제 패치 이미지가 필요하면 §6 의 코드로 좌표에서 잘라내면 된다.

## 3. 파라미터 설명

`WSITileSampler(...)` 생성 시 의미 있는 인자:

| 인자 | 본 작업 값 | 설명 |
|---|---|---|
| `root` | WSI 경로 또는 디렉터리 | 파일이면 1장, 디렉터리면 그 안의 모든 `.svs` 처리 |
| `output_dir` | `output/TCGA-LUAD` | HDF5·썸네일 저장 위치 (없으면 생성) |
| `endswith` | `"svs"` | 디렉터리 처리 시 대상 확장자 |
| `max_depth` | `0` | 디렉터리 재귀 탐색 깊이. `0` = 최상위만 |
| `save_thumb` | `True` | 켜면 `Thumbnails/` 에 썸네일 PNG 저장 |
| `tile_size` | `224` | **level-0(원본 해상도) 기준 타일 한 변(px)** |
| `overlap` | `0` | 타일 겹침 **비율**(0~1). `0` = stride 224. ⚠️ 1 이상 넣으면 stride 가 음수가 돼 0 타일 |
| `min_tiles` | `5` | 후처리: 한 조직 덩어리(contour)에 타일이 이 수 미만이면 통째로 버림. 작은 티끌 제거용 |
| `is_normalized` | `False` | stain normalization 적용 여부. 좌표만 뽑을 땐 불필요 |

**`tile_size` 와 배율(magnification)**: `tile_size` 는 항상 level-0 픽셀 기준이다.
같은 224 px 라도 슬라이드 배율에 따라 실제 조직 면적이 다르다:

| 배율 | mpp (µm/px) | 224 px 의 실제 크기 |
|---|---|---|
| 40× | 0.25 | 56 µm |
| 20× | 0.50 | 112 µm |

TCGA-LUAD 3장은 모두 **20× (mpp ≈ 0.502)** 라 224 px ≈ 112 µm 다.
다른 배율의 슬라이드를 섞어 쓸 때는 이 차이를 반드시 인지할 것.

**`min_tiles` 조정**: 조직이 깨끗하게 한 덩어리면 작게(5), 작은 파편/먼지가 많아
그것까지 버리고 싶으면 크게 잡는다 (프레임워크 주석상 BRCA 는 50~150 사용).

## 4. 내부 동작 (4단계)

`WSITileSampler` 가 WSI 1장을 처리하는 순서:

### [1/4] `load_wsi` — 슬라이드 열고 썸네일 생성
- `openslide` 로 `.svs` 를 연다.
- 피라미드 레벨 중 픽셀 수 100만 초과인 **가장 작은 레벨**을 골라 썸네일/마스크 기준으로 삼는다.
- `scaler` = 원본 ÷ 썸네일 배수. 이후 모든 좌표 환산의 기준.

### [2/4] `compute_foreground_mask` — 조직(foreground) 검출
- `ForegroundMasker` 가 썸네일에서 조직 영역만 흰색(255)인 이진 mask 를 만든다.
- 방식: CLAHE 대비 보정 → **YUV 다채널 필터**(red/green/blue) 합성 → 작은 구멍 메우기
  → HSV saturation + Otsu 로 배경 제거 → 두 결과 AND.
- 유리(빈 배경)·지방·얼룩을 배제하도록 설계됨.

### [3/4] `sample_tiles` — 타일 좌표 샘플링
- 원본 해상도에서 stride `tile_size`(겹침 0이면 224) 격자로 후보 좌표를 만든다.
- 각 후보를 mask 스케일로 환산해 검사: 중심이 조직이고 가장자리에 조직이 일정량 이상이면 채택.
- contour 클러스터 단위로 묶어 `min_tiles` 미만 덩어리는 제거.
- 멀티프로세싱(`Pool`)으로 처리.

### [4/4] `save_hdf5` — 좌표 + metadata 저장
- 채택된 좌표를 `output_dir/<name>.h5` 로 저장.

드라이버는 여기에 더해 **조직 mask PNG** 와 **타일 overlay PNG** 를 추가 저장한다.

## 5. 자기 WSI 에 적용하기

`run_tiling_tcga_luad.py` 상단의 3개 상수만 바꾸면 된다:

```python
WSI_DIR   = "/내/슬라이드/폴더"
WSI_FILES = ["slideA.svs", "slideB.svs", ...]   # WSI_DIR 기준 파일명
OUT       = os.path.join(HERE, "output", "내프로젝트")
TILE_SIZE = 224          # 필요하면 변경
```

**디렉터리 통째로 처리**하고 싶으면 드라이버 대신 `WSITileSampler.run()` 을 직접 쓸 수도 있다
(단 이때는 조직 mask 가 따로 저장되지 않는다):

```python
import sys; sys.path.insert(0, "WSI_tile_sampling_framework")
from TileSampling import WSITileSampler
WSITileSampler(
    root="/내/슬라이드/폴더", output_dir="output/내프로젝트",
    endswith="svs", max_depth=0, save_thumb=True,
    tile_size=224, overlap=0, min_tiles=5, is_normalized=False,
).run()
```

mask 까지 저장하려면 드라이버처럼 `load_wsi → compute_foreground_mask →
sample_tiles → save_hdf5` 를 직접 호출하고, `compute_foreground_mask` 가
돌려주는 `mask` 를 `cv2.imwrite` 로 저장하면 된다.

## 6. 출력물과 좌표 사용법

### 6.1 출력 디렉터리 구조

```
output/<프로젝트>/
├── <name>.h5                          # 타일 좌표 + metadata
├── Thumbnails/<원본파일명>.png         # 슬라이드 썸네일
├── Masks/<name>_tissue_mask.png       # 조직 mask (0/255) — 드라이버가 저장
└── Overlays/<name>_tiles.png          # 썸네일 위 타일 격자 (QA) — 드라이버가 저장
```

`settings.txt` 는 `output_dir` 의 **부모 폴더**에 자동 생성된다(프레임워크 사양).

### 6.2 HDF5 내용

```python
import h5py
with h5py.File("output/TCGA-LUAD/TCGA-05-4245-01A-01-BS1.h5") as hf:
    coords = hf["coords"][:]               # (N, 2) int64
    meta   = dict(hf["metadata"].attrs)    # {tile_size:224, overlap:0, total_tiles:N}
```

- `coords` = **원본 해상도(level 0) 기준 타일 좌상단 `(x, y)`**. 모두 `tile_size` 배수.
- `metadata` = `tile_size`, `overlap`, `total_tiles`.

### 6.3 좌표에서 실제 패치 이미지 잘라내기

프레임워크는 좌표만 남기므로, 패치 이미지가 필요하면:

```python
import h5py, openslide

svs   = "/.../TCGA-05-4245-01A-01-BS1.<uuid>.svs"
slide = openslide.OpenSlide(svs)
TILE  = 224

with h5py.File("output/TCGA-LUAD/TCGA-05-4245-01A-01-BS1.h5") as hf:
    coords = hf["coords"][:]

for i, (x, y) in enumerate(coords):
    patch = slide.read_region((int(x), int(y)), 0, (TILE, TILE)).convert("RGB")
    patch.save(f"patches/tile_{i:05d}_x{x}_y{y}.jpg")
```

> `read_region` 의 첫 인자는 **항상 level-0 좌표**, 세 번째가 추출 레벨에서의 크기다.
> level 0 에서 224×224 를 뜨려면 위와 같이 `(x,y), 0, (224,224)`.

## 7. 알려진 버그·한계 (반드시 읽을 것)

### A. `tile_processing.py` CLI 인자 오정렬 — **CLI 직접 사용 금지**
`WSITileSampler.__init__` 시그니처는
`(root, output_dir, endswith, max_depth, save_thumb, tile_size, overlap, min_tiles, is_normalized)`
인데, `tile_processing.py` 는 `overlap` 을 빼고 8개만 positional 로 넘긴다. 그 결과:

- `--min_tiles` 값이 `overlap` 슬롯으로 → `overlap` 이 비율 5 가 됨
- `stride = tile_size − tile_size×overlap = 224 − 224×5 < 0` → 격자 루프가 비어 **타일 0개**
- `--is_normalized` 가 `min_tiles` 슬롯으로 들어감

→ 기본값으로 CLI 를 돌리면 결과가 빈다. **§2 의 드라이버(명시적 kwargs)를 쓸 것.**
CLI 를 꼭 살리려면 `tile_processing.py` 의 생성자 호출에 `overlap` 인자를 추가해야 한다.

### B. `filter_tiles_by_boundary` centroid 오프셋 — **수정 완료**
`Tiling.py` 의 이 함수는 타일이 어느 조직 contour 에 속하는지 판정할 때 centroid 를
**썸네일 좌표계**에서 구한다. 그런데 타일 반 변을 더할 때 `round(self.tile_size)`
(= 224, 다운스케일 미적용)를 써서 centroid 가 우하단으로 ~112 px(썸네일 px) 치우쳤다.
그 결과 모든 조직 contour 의 우·하단 가장자리에서 ~112 px 폭의 타일 띠가 통째로
누락 — 타일 격자가 **좌상단 기준 대각으로 ~5–8 % 축소**돼 보였다
(TCGA-LUAD 3장에서 타일 13–19 % 누락).

→ `round(self.tile_size / self.downscale_factor)` 로 수정 완료
(`Tiling.py` `filter_tiles_by_boundary`). 수정 후 우하단 비대칭이 사라지고
타일 수가 2,525→2,869 / 1,567→1,871 / 9,117→10,661 로 회복됐다.
`raw sample_tiles` 결과와 거의 일치(차이 ≤5 타일)하므로, 수정된 contour 후처리는
실제로 5 타일 미만의 미세 클러스터만 떨군다(원래 의도대로).

### C. 썸네일 레벨 / scaler 불일치 가능성
`load_wsi` 는 썸네일을 항상 최소 레벨 크기로 만들지만 `scaler` 는
`level_downsamples[thumbnail_level]` 로 잡는다. 최소 레벨의 픽셀 수가 100만 이하면
`thumbnail_level ≠ -1` 이 되어 둘이 어긋날 수 있다.
TCGA-LUAD 3장은 최소 레벨이 모두 100만 초과라 `thumbnail_level = -1` → 정상 동작.
다른 슬라이드를 쓸 땐 실행 로그의 `scaler` 값과 썸네일 크기가 맞는지 확인할 것.

### D. 배율
좌표·`tile_size` 는 level-0 기준이라 정확하지만, 224 px 의 *물리적 크기*는
배율에 따라 다르다(§3). 다운스트림 모델이 특정 mpp 를 가정하면 별도 리샘플 필요.

### E. 썸네일 PNG 가 matplotlib savefig 로 리스케일됨
`load_wsi` 는 `save_thumb=True` 일 때 썸네일을 `plt.imshow → plt.savefig(bbox_inches='tight')`
로 저장한다(`TileSampling.py:149-158`). 이 경로는 배열을 matplotlib figure 캔버스에
다시 렌더한 뒤 crop 하므로, 저장된 `Thumbnails/*.png` 가 **실제 썸네일 배열보다 작고
슬라이드마다 크기가 제각각**이 된다 (예: 2250×2490 배열 → 333×369 PNG).
드라이버가 `cv2.imwrite` 로 저장하는 `Masks/`·`Overlays/` 는 실제 배열 해상도라,
셋을 겹쳐 보려 하면 `Thumbnails/` 만 좌표계가 안 맞는다. 타일 좌표·HDF5 에는
영향 없는 미리보기용 결함이며, `prepare_wsi_for_inference_v2.py` 는 이 문제 때문에
`openslide.get_thumbnail()` 직접 저장 경로를 쓴다(`report/03` §2 참조).
본 파일럿 산출물의 `Thumbnails/` 는 openslide 썸네일 배열 그대로 재저장해
`Masks/`·`Overlays/` 와 크기(2250×2490 등)를 일치시켜 두었다.

### QA overlay

붉은 격자가 채택된 224×224 타일 위치다. 조직 영역만 조밀하게 덮이고
배경·찢김·내부 구멍은 제외된 것이 정상 동작의 근거다.

**TCGA-05-4245-01A-01-BS1** (2,869 타일) — 조직 본체는 균일하게 덮이고,
가장자리 빈 공간과 내부의 흰 구멍(조직 손실부)이 타일링에서 빠져 있다.
§7-B 수정 후 빨간 격자가 우·하단 조직 경계까지 닿는다.
